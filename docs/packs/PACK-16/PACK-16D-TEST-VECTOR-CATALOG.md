cited as any part of it.** The classes of evidence that _are_ live in a
separate artefact,

### 1.0 Five conformance classifications, and this catalogue is the one that is not evidence

`EvidenceClass` now has **five** members, not three. The previous round
used one `cross-implementation` label for everything an independent oracle
checked, and an audit then found that most of those checks ran on the
1024-bit test profile — which the single label made invisible. A
cross-check on a group the election will never use and a cross-check on
`EPD2-CRYPTO-1` are different evidence, so they are now named and counted
separately. `rfc-conformance` was likewise split out of `primary-source`,
because an RFC's published vectors are the strongest evidence a
_primitive_ can have and conflating them with protocol-parameter
provenance made both harder to audit.

`PACK-16D-CONFORMANCE-EVIDENCE.json` is `catalog_version
EPD2-CONFORMANCE-2` with **26 entries**:

```text
internal-stability                     0   (deliberately — never promoted here)
primary-source                         1
rfc-conformance                        1
cross-implementation-test-profile      8
cross-implementation-target-profile   16
```

### 1.1 Every expected output in this catalogue changed this round

The vector **count** is unchanged at 23 and no vector was added, removed or
renumbered. **Every `expected_output` value moved**, and the reason is a
single defect in the canonical encoder.

| ID      | Statement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VC-55` | **`encode_seq` and `encode_struct` were ambiguous and now length-prefix.** `encode_seq` wrote a four-byte count and then concatenated the items _raw_, so `SEQ([b"ab", b"c"])` and `SEQ([b"a", b"bc"])` flattened to identical bytes — two different sequences sharing a digest. `encode_struct` appended field values raw for the same reason. Both now emit `BYTES(item)` per element, which is what the documented grammar in the module docstring always said (`SEQ = UINT(len,4) \|\| BYTES(item)...`)            |
| `VC-56` | **It was found by the independent cross-implementation oracle, not by this catalogue.** `tests/reference/crossimpl/independent_verifier.mjs` was written from the written grammar rather than from the Python, disagreed with the code, and that disagreement is what surfaced the defect. This is precisely the class of error a self-generated vector cannot find: an error made consistently by one implementation is invisible to a stability check, because the check compares that implementation against itself |
| `VC-57` | **Every digest in the round therefore changed, and the stability vectors duly caught it.** `test_regenerating_the_catalog_is_byte_identical` failed until the committed catalogue was re-decided against the corrected encoder, which is the mechanism `VC-41` and `VC-42` describe working exactly as intended: the catalogue detected that a canonical form had moved, and the response was a decision about which of the two encoders was right, not a regeneration                                                 |
| `VC-58` | **What this episode establishes about the catalogue's value, stated without inflation.** The catalogue proved it can detect a canonical-form change. It did **not**, and could not, detect that the canonical form was _wrong_. Only the independent oracle did that, and that asymmetry is the whole argument for keeping the evidence classes apart                                                                                                                                                                  |

## 2. The 23 vectors

At least one vector per §38 family, in the order §38 lists them.
`REQUIRED_FAMILIES` in `test_vectors.py` names twenty families; there are
twenty-three vectors because `verification result` carries two (`TV-20`
for a single result object, `TV-21` for the whole exit-code table), and
`parameter validation` and `group element encoding` each carry a second
vector on the 4096-bit TEST profile (`TV-22`, `TV-23`).

Thirteen vectors are generated on the `EPD2-TESTONLY-NOTCONFORMANT-P1024-Q160` profile —
`small_params()`, the fast TEST profile. Two are generated on
`EPD2-TESTONLY-NOTCONFORMANT-P4096-Q256`, so the catalogue is not built entirely on the
small profile. Eight are profile-independent (hashing, Merkle, leaf
construction, result codes) and record `profile_version` as `n/a`. **No
vector in the committed catalogue is generated on a production profile,
and none can be**; see `VC-47`.

## 4. The regeneration test, and what a failure of it means

`test_regenerating_the_catalog_is_byte_identical` regenerates the whole
catalogue in memory and compares it against the committed text as a single
string.

```python
regenerated = serialize(build_catalog())
committed = CATALOG_PATH.read_text()
assert regenerated == committed
```

| ID      | Rule                                                                                                                                                                                                                                                                                                                             |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VC-41` | **A failure means exactly one of two things, and the assertion message says both.** Either a canonical form changed — encoding, domain separation, hashing or a proof transcript — or the committed file was edited by hand                                                                                                      |
| `VC-42` | **Both are decisions, not merges.** The correct response is never "regenerate and commit". It is to determine which of the two happened, decide whether the change was intended, and record that decision. Regenerating first destroys the evidence that would answer the question                                               |
| `VC-43` | A changed canonical form is a compatibility break for anything that already consumed an artefact of this implementation. A hand-edited file is a corrupted baseline: it no longer pins what the implementation does, which is the only thing the catalogue is for                                                                |
| `VC-44` | `test_generation_is_deterministic_across_runs` builds the catalogue twice in one process and asserts the two serialisations are equal. This separates "the implementation changed" from "the generator is not deterministic" — if this test fails too, the fault is non-determinism in generation, not drift in a canonical form |
| `VC-45` | `test_each_vector_output_is_stable` is parametrised over all 23 indices, so a failure names the single vector that moved rather than reporting one large string diff. It asserts both the `vector_id` and the `expected_output` at each index, which also pins the order                                                         |

## 5. The two honesty tests

Two tests exist solely to stop a vector from claiming more than it has.
They assert nothing about cryptography; they assert about the claim.

| ID      | Test                                       | What it enforces                                                                                                                                                                                                                                   |
| ------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VC-46` | `test_no_vector_claims_interoperability`   | The catalogue's top-level `provenance` equals `SELF_GENERATED`, and **every** vector's `source` equals `SELF_GENERATED` and `status` equals `STATUS_STABILITY`. A vector cannot be given a softened source string or a status implying conformance |
| `VC-47` | `test_no_vector_uses_a_production_profile` | Every vector's `profile_version` is one of `EPD2-TESTONLY-NOTCONFORMANT-P1024-Q160`, `EPD2-TESTONLY-NOTCONFORMANT-P4096-Q256` or `n/a`, and is explicitly asserted not to be `EPD2-CRYPTO-1`. The failure message names the offending vector id    |

| ID      | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VC-48` | **These tests fail on a documentation change, which is the point.** Softening the provenance string in `vectors.py` to something more comfortable breaks the suite. The honest string is load-bearing, not decoration                                                                                                                                                                                                                                                                                          |
| `VC-49` | `VC-47` was written as a guard against a round wiring the real target profile into the generator without re-examining what the vectors then claim. **That round has now happened** — `EPD2-CRYPTO-1` loads — and the guard did its job: the generator was left alone and the catalogue still runs on TEST profiles only. A vector generated on `EPD2-CRYPTO-1` would still be self-generated and still not an external conformance vector, so the shortcut it refuses is exactly the one that became available |
| `VC-50` | Neither test can be satisfied by a vector that is merely _labelled_ correctly while being generated some other way. They are a floor, not a proof of provenance. The provenance claim ultimately rests on `build_catalog()` being readable in full — it is one linear function in which every vector's construction is visible                                                                                                                                                                                 |

## 6. What this catalogue does not establish

Stated in the body, not in a footnote, because it is the part most likely
to be misread:

- **No conformance evidence of any kind.** These 23 vectors are
  `internal-stability` and nothing else. They are **not** conformance
  evidence, they may not be counted toward it, and the round's actual
  conformance evidence — 26 entries: 1 primary-source, 1 rfc-conformance,
  8 cross-implementation-test-profile and 16
  cross-implementation-target-profile — is in
  `PACK-16D-CONFORMANCE-EVIDENCE.json` and
  `PACK-16D-EXTERNAL-CONFORMANCE-REPORT.md`. That catalogue's
  `internal-stability` count is `0` on purpose (`VC-61`). `VC-46` enforces
  the label here by test.
- **No interoperability.** Agreement with a complete ElectionGuard
  implementation is unestablished (`OD-P16D-02`). A green vector suite says
  this implementation is stable against itself, and nothing further. The
  two independent oracles added this round narrow that gap; they do not
  close it, and neither of them is this catalogue.
- **No production-parameter evidence from _these_ vectors.** Thirteen run
  on a 1024-bit TEST profile chosen for speed and two on the 4096-bit TEST
  profile, which shares `EPD2-CRYPTO-1`'s shape and its `q` but not its
  constants. `VC-47` asserts by test that **no** vector here is generated
  on `EPD2-CRYPTO-1`, and that remains true now that the target profile
  loads and now that twelve core operations are cross-checked on it — the
  guard was written for exactly this situation. Evidence _on_
  `EPD2-CRYPTO-1` exists in the conformance catalogue and in the exported
  target-profile fixtures (`VC-65`) instead.
  `production_use_permitted` is `False` on every registered profile, and
  `VO-08` — whether the parameters are appropriate — is **OPEN**. No BSI
  conformity is claimed.
- **No timing claim.** Python big-integer arithmetic is not constant-time,
  and the vectors say nothing about side channels (`OD-P16D-05`).
- **No multi-guardian evidence _in this catalogue_.** `TV-12` is a
  single-share decryption vector and stays one. Threshold DKG with a 3-of-5
  and 4-of-7 quorum **is** implemented this round in
  `reference/guardians/`, and the evidence for it is in `test_guardians.py`,
  in E2E-11 … E2E-14 and in the cross-implementation threshold-tally vector
  `CV-11` — not here. `OD-P16D-07` is closed; no vector in this catalogue
  was changed to reflect that.
